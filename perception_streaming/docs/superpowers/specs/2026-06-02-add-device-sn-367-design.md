# 新增设备 SN LK-MR641US000367 与 SSH 秘钥切换设计

日期：2026-06-02

## 背景

前端设备配置面板当前提供设备 SN 下拉选择，并通过现有连接逻辑根据 SN 更新连接端口。当前 SSH 配置使用 `bestmow_rsa_202605` 私钥。需要新增设备 `LK-MR641US000367`，并将连接使用的 SSH 私钥切换到 `data/conf/bestmow_rsa_202606`。

## 目标

- 设备 SN 下拉列表展示 `LK-MR641US000367`。
- 新设备连接端口映射为 `10367`。
- SSH 私钥配置切换为 `bestmow_rsa_202606`，对应文件路径为 `data/conf/bestmow_rsa_202606`。
- 保持现有设备与连接逻辑不变。

## 非目标

- 不重构设备列表配置结构。
- 不迁移硬编码设备列表到统一配置文件。
- 不改变 Agora、MQTT 或其他分析面板行为。

## 方案

采用最小配置变更：沿用当前代码中的设备 SN 下拉框和 SN 到端口映射模式，只补充新设备条目，并更新 SSH 配置文件中的私钥名称。

## 影响范围

- `src/components/DevicePanel.vue`：新增设备 SN 下拉选项 `LK-MR641US000367`。
- `src/composables/useObstacleMonitor.ts`：新增 SN 到端口映射 `LK-MR641US000367: 10367`。
- `data/conf/ssh_config.json`：将 `ssh_key_path` 从 `bestmow_rsa_202605` 改为 `bestmow_rsa_202606`。

## 数据流

1. 用户在设备配置面板选择 `LK-MR641US000367`。
2. 现有监听逻辑读取 SN，并调用现有端口更新逻辑。
3. 端口映射返回 `10367`，连接表单使用该端口。
4. 后端或相关配置读取 `data/conf/ssh_config.json`，使用 `bestmow_rsa_202606` 作为 SSH 私钥文件名。

## 错误处理

- 如果新设备 SN 未匹配到端口映射，现有逻辑会保持当前端口或回退现有行为。本次通过新增映射避免该问题。
- 如果 `data/conf/bestmow_rsa_202606` 文件缺失，连接阶段会按现有 SSH 错误路径失败；本次不新增文件存在性校验。

## 测试与验证

- 静态检查确认下拉列表包含 `LK-MR641US000367`。
- 静态检查确认 SN 映射为 `10367`。
- 静态检查确认 `ssh_key_path` 为 `bestmow_rsa_202606`。
- 如项目测试可运行，则执行现有前端或回归测试，确认未破坏现有逻辑。

## 决策

已选择最小配置变更方案。该方案改动范围最小，符合当前代码结构，适合本次只新增单个设备与切换秘钥的需求。
